# ADR-0006: 验证策略——fixture 先行，真实站点延后回归

- 状态：已接受（2026-09-26）
- 背景：当前无淘宝直播登录态，无法在 liveplatform 真实页面上验证。
- 决策：
  - 现在可验：① 机制冒烟（窗口/分区创建、隐藏执行、隐藏态截图、防节流生效）；② C32 fixture 全链路——按扩展生产验证过的选择器构建本地 mock 页（列表页 + 详情页 + 三类弹窗），`scripts/test-c32-fixture.mjs` 断言完整流程（含已置顶跳过、替换上限弹窗、失败截图与恢复）；③ 定时 + 多账号并发对 fixture 页执行。
  - 延后回归（遗留验收门）：用户开播后，真实扫码登录 → userNumId 捕获 → 真实页面跑通置顶 → 风控灰度观察。
- 理由：DOM 选择器直接移植自生产验证过的扩展代码，fixture 与真实页面同源构建，漂移风险可控；机制性问题（节流、隐藏截图、并发）与站点无关，可先行锁死。
